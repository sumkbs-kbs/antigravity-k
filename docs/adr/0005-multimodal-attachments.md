# ADR-0005. 첨부(이미지) 전달 계약 — 바이트가 모델에 가거나, 명시적으로 거부한다

- 상태: **수용(Accepted)** — 2026-09-16, NX-09-F03 작업 중
- 관련: `docs/18` §NX-09 / `docs/19` §NX-09, `docs/19` §NX-10(후보 고정), `docs/20`(현재 상태)
- 구현 소유자: `src/antigravity_k/engine/multimodal.py` (파싱·검증·표면 변환의 단일 소유자)
- 증거: `docs/qa/2026-09-16-followup/nx09/f03/**` (계약 시험 `tests/test_nx09_f03_multimodal_attachments.py`, 증인 T4, 추적 탐침)

## 1. 문제

화면은 파일을 고르면 `[첨부 파일: <name>]` **텍스트만** 입력창에 넣고 바이트는 어디에도 보내지
않았다. 사용자는 이미지를 붙였다고 믿지만 모델은 파일명만 본다 — 화면이 거짓말을 했다
(NX-09-F03, 증인 T4 가 `test.fail` 로 고정하고 있었다). 실측으로 확인한 손실 지점은 하나가
아니었다: ① 요청 스키마에 첨부 채널이 없었고, ② 관리자 스트림 준비가 파트 배열을 **텍스트로
납작하게 만들어** 이미지를 버렸고(`_prepare_stream_messages`), ③ 에이전트 경로는 프롬프트
문자열 기반이라 애초에 이미지가 지나갈 자리가 없었고, ④ provider 어댑터들이 각자 메시지를
다시 만들면서 같은 방식으로 버렸으며, ⑤ 첨부를 파트 배열로 실어 보내면 `content` 를 문자열로
가정하는 코드(정규식·`.strip()`·SQLite 바인딩·스냅샷 스키마)가 **500 으로 죽었다**.

## 2. 결정

1. **요청 표현**: `POST /v1/chat/completions` 본문의 `attachments: [{name, mime_type, data_base64}]`.
   마지막 user 턴에 붙는다. 파일명 텍스트 표식(`[첨부 파일: <name>]`)은 이력 참조용으로 남긴다.
2. **검증**: 허용 형식 `image/png|jpeg|webp|gif`, 개별 ≤5MiB, 합계 ≤12MiB, 최대 4개.
   위반은 **400 + 기계 판독 가능한 사유**(`unsupported_attachment_type` · `attachment_too_large`
   · `too_many_attachments` · `invalid_attachment_encoding` …)로 거부한다. **조용한 대체·조용한
   폐기는 금지** — 그것이 이 결함의 본질이었다. 화면은 서버 사유를 toast 로 보여 준다.
3. **내부 정규형**: 메시지의 `content` 는 **항상 문자열**, 이미지는 `images`(base64 배열) +
   `image_mimes`(형식 배열). 이유는 이 저장소에 `content` 를 문자열로 가정하는 코드가 많기
   때문이다 — 파트 배열로 돌아다니면 그 자리들이 전부 죽는다(실측 500). OpenAI 호환 표면처럼
   `content: [{type: "image_url"}]` 로 들어오는 요청은 **끌어올려** 같은 정규형으로 만든다.
4. **표면 변환은 한 곳에서**: OpenAI 호환은 파트 배열, Ollama 네이티브는 `content` + `images`,
   Anthropic 은 `source.base64` 블록. 어댑터는 `multimodal.adapter_messages(surface=...)` 하나만
   부른다(어댑터마다 따로 풀면 버리는 자리가 계속 생긴다 — 실제로 그렇게 샜다).
   변환할 수 없는 입력(원격 URL 등)은 **버리지 않고 거부**한다.
5. **에이전트 경로**: 모델 입력이 프롬프트 **문자열**이라(압축·예산 게이트가 문자열을 전제)
   이미지는 프롬프트 예산 계산에 끼어들지 않고 별도 채널(`images` kwarg)로 실린다.
6. **저장 표현**: 대화 저장소·태스크 스냅샷에는 **텍스트만** 남는다(base64 를 디스크에 넣어
   저장소를 부풀리지 않는다 — NX-03/NX-08 의 저장 불변식 유지). 따라서 **이미지는 그 턴에만**
   모델에 간다: 이어지는 턴은 파일명 표식만 본다. 이 한계는 제품 문구로도 정직해야 한다.
7. **tools passthrough 경로**에서는 첨부를 지원하지 않으며, 요청이 오면 400 으로 거부한다
   (그 경로는 메시지를 그대로 provider 로 넘기므로 첨부가 조용히 사라진다).

## 3. 결과

- 첨부가 실제 바이트로 모델에 도달한다(증인 T4: provider 본문에 PNG base64, 표면 `/api/chat`).
- 다음 턴에는 재전송되지 않는다(T4 가 함께 단언) — 저장 정책과 일치.
- 거부 사유가 사용자에게 보인다(화면 toast + 400 본문).
- 비용: 요청 본문이 커진다(=첨부 크기). 저장소는 커지지 않는다(정책).
- 후속 결정 필요: **이전 턴 이미지의 재전송**(대화를 이어 갈 때)과 **압축된 대화에서의 첨부
  의미 보존**은 이 ADR 의 범위 밖이다(별도 카드).
