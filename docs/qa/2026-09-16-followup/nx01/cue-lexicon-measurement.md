# NX-01 후속 — cue lexicon **회수율·오검출** 측정 (설계 + 이번 실측)

작성: 2026-09-16. 코드 동결 지문 `157311cf…`(동결 중 측정 — 어휘를 고치지 않았다).
근거: `cue_lexicon_probe.py` · `cue-lexicon-output.txt`(실제 실행 출력) · `handoff.md` §6-1.

## 1. 이 문서가 닫는 것 / 닫지 않는 것

`nx01/handoff.md` §6-1 은 한계를 이렇게 적었다: *"제약 구조화는 결정론적 어휘 목록에 의존한다.
목록 밖 표현의 요구사항은 구조화되지 않는다. **회수율은 별도 실측으로 확인해야 한다**"*. NX-09 는 그
측정을 하지 않았고(`tests`/`nx09` 기록 참조), 그래서 `docs/19` 에 **소유자 미정 · 미실측**으로 남아 있었다.

이번에 한 것: **어휘 자체의 성능**을 합성 코퍼스로 측정하고, 실제 경로(`update_from_messages`)에서
**피해가 발생하는지**까지 확인했다.

하지 않은 것: **실사용 회수율**. 그건 라벨링된 실데이터 코퍼스가 필요하고(§5), 프라이버시·라벨러·소유자
결정이 먼저다. 그러므로 여기서 "사용자 요구사항을 보존한다"고 주장하지 않는다 — 주장 경계는 §6.

| 코퍼스 | **이 문서 작성을 위해 새로 만든 합성 문장** — 사용자 데이터·대화 내용은 넣지 않았다(그래서 결과를 그대로 문서에 실을 수 있다) |
| 규모 | 메시지 29건(패밀리 A/B/C) · supersede 7건 · end-to-end 시나리오 6건 |
| 실행 | `python3 scripts/cue_lexicon_probe.py` (2026-09-16 승격 완료 — 그 전에는 `docs/qa/2026-09-16-followup/nx01/`; 다시 돌리면 같은 결과) |
| 어휘 수정 | **없음**(측정만) |

## 3. 결과

### 3.1 메시지 → kind 판정

| 패밀리 | 정확도 | 뜻 |
|---|---|---|
| **A. 사전 안의 직접 표현** | **9/10** | 사전에 있는 말로 쓰면 잡힌다. 1건은 **종류 오분류** |
| **B. 같은 뜻, 사전 밖 표현** | **0/12** | **전부 놓쳤다** — 자연어 바꿔쓰기에 사실상 무방비 |
| **C. 사전 단어가 들어간 잡담** | 1/7 | 6건이 제약으로 **잘못 승격**(이 패밀리는 *일부러* cue 를 넣어 만든 스트레스 집합) |

- A 의 오분류: `"배포 전에 반드시 나에게 물어봐"` → `requirement`(기대 `approval`).
  원인: `반드시`(requirement cue)가 먼저 잡히고, `물어봐` 는 approval cue 목록에 없다
  (approval cue 는 `승인/허가/동의/허락/먼저 물어/확인 후/물어보고/approval/approve/permission/ask before/confirm before` 8종).
- B 의 예(모두 실제로 놓친 문장): `"네트워크는 꺼 두고 작업해줘"`, `"외부로는 나가지 않게 해줘"`,
  `"Avoid touching production"`, `"그건 실행하기 전에 나한테 알려줘"`, `"이 부분은 그대로 두는 게 좋아"`,
  `"그 값은 바뀌면 안 돼"`.
- C 의 예: `"mustard 색으로 바꿔줘"` → **requirement**(`must` 부분일치), `"이 버그 재현되면 blocking 인지 봐줘"`
  → prohibition(`block`), `"오프라인 미팅 얘기가 있었어"` → prohibition, `"keep going, 결과만 보여줘"` → requirement.
  판정은 `_normalize` 후 **부분 문자열 포함 검사**라 단어 경계가 없다.

### 3.2 supersede 판정 (cue 수준)

7건 중 5건 정확. 오류 2건은 둘 다 **거짓 양성**이고 원인은 cue 목록에 일상 단어가 들어 있는 것:
`"이 파일 좀 변경해줘"`(`변경`) · `"그거 대신 이걸로 해줘"`(`대신`).

### 3.3 실제 경로에서 **피해가 나는가** (핵심)

cue 오검출은 그 자체로 피해가 아니다 — supersede 는 **토큰 교집합**이 있어야 발동하므로, 조건이
성립하는 현실적 시나리오로 확인했다. 6개 중 3개가 기대와 다르게 나왔다:

| 시나리오 | 결과 | 해석 |
|---|---|---|
| 명시적 해제 (`더 이상 …`) | `superseded` | **정상**(양성 대조군) |
| 다른 주제 편집 요청 | `active` | 정상 — 토큰 교집합이 없어 유지 |
| 같은 파일 + `변경` | `active` | 정상(한국어 조사 때문에 토큰이 안 겹친다) |
| **승인 규칙 표현이 사전 밖** | **`absent`(아예 생성 안 됨)** | **피해 ①** — `"변경 전에는 먼저 확인해줘"` 는 승인 규칙인데 구조화되지 않는다. B 패밀리의 실제 경로판 |
| **영문 `instead` + 토큰 교집합** | **`superseded`** | **피해 ②** — `"Always keep the deploy rule"` + `"Use instead the new deploy config"`: 상시 규칙이 **편집 지시 하나로 무효화**됐다(`instead` cue + `deploy` 겹침) |
| **평범한 요청의 제약 승격** | **`active`(requirement)** | **피해 ③** — `"mustard 색으로 바꿔줘"` 가 상시 요구사항으로 저장됐다 = 프롬프트 오염 |

피해 ②③ 의 영향: ② 는 `superseded` 로 내려간 제약이 렌더 블록에서 빠지므로(최근 3건만 렌더) **사용자가
말한 상시 규칙이 조용히 프롬프트에서 사라진다** — 항목 자체는 남지만 모델은 다시 보지 못한다.
③ 은 반대로 평범한 지시가 **상시 정책 문장으로 승격**되어 이후 모든 프롬프트에 실린다. 누적 상한(active 128)도
있어 오염이 계속 쌓인다.

두 피해 모두 **메모리 안에서 사후 확인·수정이 가능**하다(항목이 삭제되지 않고 status 만 바뀐다)는 점이 완화 요인이다.

## 4. 이 결과로 주장할 수 있는 것 / 없는 것

- **주장 가능**: "사전 표현으로 명시된 규칙은 압축 세대를 넘어 보존된다(계약 시험 10건)" +
  "사전 밖 표현은 구조화되지 않으며, 실측한 합성 스트레스 집합에서 12/12 놓쳤다".
- **주장 불가**: "사용자 요구사항이 보존된다"(§5 실측 전), "오검출률 X%"(C 패밀리는 일부러 cue 를 넣은
  스트레스 집합이므로 **모집단 비율이 아니다** — 존재 증명일 뿐이다).
- NX-07 지원표에 반영할 문구는 위 "주장 가능" 범위까지만이다.

## 5. 실사용 회수율 측정 설계 (다음 소유자용 — 아직 미실시)

| 항목 | 설계 |
|---|---|
| 코퍼스 | 실제 사용자 턴 **≥ 100건**(한/영), 의도적으로 사전 밖 표현을 다수 포함. **표본 출처는 운영 결정**(사용자 동의 필요) |
| 라벨 | 각 턴을 `requirement / prohibition / approval / not_constraint` 로 사람이 라벨. **라벨러 2인 + 불일치 조정 회의**, 일치도(Cohen κ) 기록 |
| 프라이버시 | 라벨 파일은 **저장소 밖**(예: `~/.antigravity/qa-labels/`)에 두고, 저장소에는 **집계 수치만** 커밋한다. 원문·부분문자열 금지 — 이 문서가 합성 문장만 쓴 이유와 같다 |
| 지표 | ① 승격 정밀도(라벨이 `not_constraint` 인데 제약이 된 비율의 여집합) ② **무효화 정밀도**(거짓 supersede 비율의 여집합) ③ 명시 규칙 회수율 |
| 제안 임계 | 승격 정밀도 **≥ 0.90** · 무효화 정밀도 **≥ 0.95**(상시 규칙을 잘못 내리는 쪽이 더 해롭다) · 명시 규칙 회수율 **≥ 0.60**. **제안이며 오너 승인 필요** |
| 산출물 | 새 증거 디렉터리 `nx01/real-corpus-measurement/`(집계 JSON + 라벨러 일치도 + 원문 없는 표) |
| 실행 주체 | **소유자 미정** — NX-01 후속 또는 NX-07(문서·지원 범위) 중 하나로 지정 필요 |
